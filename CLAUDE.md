# polyx-lens — working notes for an agent

The free half of polyx, Apache-2.0: the canonical record, the ingest
adapters, the alphabet and redaction, the four ports with two implementations
each, and the compliance report. `README.md` says what it is. The wider
system's rules are in `../polyx/CLAUDE.md`; this file is the part that is
specific to this package.

## One claim this package makes, and the check that keeps it true

**"No mining, no model call, nothing leaves the machine."** That is the first
line of `package.json`'s description and the reason a reader can use this
package without reading a licence. `npm run check:offline` scans `src/` for
anything that could make a network call — `node:http`, `fetch`, an HTTP
client dependency, a vendor API key — and fails the build on any of them.
The Jev adapter lives in polyx, not here, precisely so that this passes.

Do not add a network dependency to this package for any reason. If a feature
needs one, it belongs in polyx behind a port defined here.

## What polyx sees

polyx consumes this package through `dist/`. After any change under `src/`:

```
npm run build
```

Then run polyx's suite too; it exercises paths this package's tests do not.
`npm run ci` here is typecheck, `check:offline`, build, test — in that order.

## Ports have two implementations

Segmentation, subjects, provenance, observation, text: each port ships a
reference implementation and a second one (polyness, vendored under
`src/ports/polyness/`; the Jev observer, in polyx). A port with one
implementation is a wish. If you add a port, add both.

`nullObserver` and `nullTextSource` are the **defaults**, not alternatives:
a deployment that has not opted in should not be able to tell the port
exists.

## Fixtures are oracles

`fixtures/synthetic/` and `fixtures/synthetic-observable/` are generated by
their `generate.mjs` with planted structure that tests in both repositories
read exact counts from. Never edit the JSON; change the generator and
regenerate. `fixtures/synthetic-observable/annotate.mjs` regenerates the
committed annotation file, and its digest is asserted in polyx.

`fixtures/synthetic/seeded.json` lists identifiers seeded into the fixture
text so redaction scans can prove they never reach a stored artefact. If you
add a text-carrying fixture, seed it and add it to that scan.

## Reviewed artefacts

Everything under `alphabets/` — `alphabet.*.yaml`, `predicates.*.yaml`,
`text.*.yaml` — is a reviewed, versioned artefact. A change to one moves
every figure derived from it. Bump the version; say why in the commit.

A predicate set's `calibration.corpusRevision` pins the corpus it was
measured on. A different revision makes the predicate **stale and inert**
(JF3.5), by design. That is not an error to route around.

## Editing

Comments explain *why* and cite the requirement id. On Windows under Git
Bash, a heredoc corrupts backslash escapes and template-literal apostrophes;
use the file-edit tools for anything containing either.
